# EVIDENCE — verified artifacts

This folder is the **proof layer** for GhostCode. Every file here is a real artifact produced by the code in `engine/` and `src/`. Nothing is hand-edited; everything is regenerated by the verification commands in [`VERIFICATION.md`](./VERIFICATION.md).

## Layout

```
EVIDENCE/
├── canonical-capture.json     ← the assembled ghost from a real run
├── sample-vault.jsonl          ← the raw JSONL vault, 13 events
├── VERIFICATION.md             ← exact commands + expected output
├── samples/                    ← individual artifacts for the website
│   ├── 01-session-start.json     env scrubbed, PII redacted at capture
│   ├── 02-inbound-request.json   one real captured HTTP request
│   ├── 03-inbound-response.json  the matching response
│   ├── 04-session-end.json       session summary
│   ├── 05-ghost-summary.json     the assembled Ghost (top-level fields)
│   ├── 06-throw-frame.json       one TimelineFrame at the throw site
│   ├── 07-clean-frame.json       one TimelineFrame for a normal request
│   └── 08-snapshot-stats.json    aggregate stats
├── transcripts/
│   └── demo-run.txt            ← raw stdout/stderr of `npm run demo:clone`
└── test-outputs/
    └── test-run.txt            ← raw stdout of `npm test` (14/14 pass)
```

## What each file proves

### `canonical-capture.json` (21 KB)
A complete `Ghost` object — the input the dashboard consumes. Generated by `engine/bin/integration-test.mjs` which:

1. Calls `enable({vault})` to install the HTTP sidecar
2. Imports `engine/demo/target-app/server.mjs` (a real Node http.Server, no Express)
3. Drives 5 HTTP requests through it (4 auth + 1 health)
4. Reads back the JSONL vault
5. Calls `assembleGhost(events)` to synthesize a `MemorySnapshot` with frames
6. Writes the assembled ghost as JSON

**Proof of life**: contains real `capturedAt` timestamps, real `latencyMs`, real `stack` frames derived from the actual request URLs, real PII masking in the captured JWT payload.

### `sample-vault.jsonl` (13 lines, one JSON event per line)
The raw vault. Every line is one capture event:

- 1× `session_start` (env captured, secrets redacted)
- 1× `inbound_request` to `/health` (200 OK)
- 1× `inbound_request` no auth → 401
- 1× `inbound_request` bad token → 401
- 1× `inbound_request` malformed → 401
- 1× `inbound_request` PII payload (email scrubbed) → 401
- 5× `inbound_response` (status, headers, latency)
- ~1× per-uncaught event if any

**No raw PII on disk.** Search for `@example.com` or `Bearer eyJ` in this file → 0 results. PII Shield applied at capture time.

### `samples/06-throw-frame.json` (4 KB)
A single `TimelineFrame` showing the inspector at the throw site. Includes:

- `stack[3]` marked `isThrowSite: true` on `validateSignature`
- `scope.err = { type: 'object', value: 'JsonWebTokenError: invalid signature', references: ['heap-err'] }`
- `heap[]` with the 4 allocations tracked at this frame
- `log: "GET /api/auth/login -> 401 (Nms)"`

### `test-outputs/test-run.txt`
Raw output of `npm test`. **14/14 pass.** Includes:
- 8 PII Shield tests (mask, no-mask, recurse)
- 1 timeline integrity test
- 1 inspector files present
- 3 clone engine tests (files, ghost validity, vault JSONL format)

### `transcripts/demo-run.txt`
Raw output of `npm run demo:clone`. Captures the entire flow:
- Sidecar enables
- Target imports
- 4 auth requests get 401s with real error messages
- 13 events captured
- Ghost assembled

## How to regenerate every artifact

```bash
cd E:\ghostcode-build

# Run tests
npm test                          # → EVIDENCE/test-outputs/test-run.txt

# Run the demo
npm run demo:clone                # → engine/demo/vault/{session.jsonl,ghost.json}

# Refresh the canonical evidence
Copy-Item engine/demo/vault/ghost.json     EVIDENCE/canonical-capture.json -Force
Copy-Item engine/demo/vault/session.jsonl  EVIDENCE/sample-vault.jsonl -Force
```

See [`VERIFICATION.md`](./VERIFICATION.md) for the exact commands and what to look for.
